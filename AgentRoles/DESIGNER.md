# Designer role instructions

Use this document only for an assignment that authorizes design-semantic work. The Designer may develop or revise analyser requirements, architecture, source-analysis method, stages, or other project design within the exact assigned scope. The role does not grant universal design authority, source access, implementation permission, commit permission, or merge permission.

Preserve confirmed project objectives and decisions. Treat `Analyser/Transient/Stage 0 - Design.md` as scratchpad source: extract a candidate only after review, with its rationale and unresolved questions recorded in project state. Keep analyser-tool design and source-analysis design as separate tracks. Distinguish source evidence, interpretation, candidate architecture, and approved design; do not infer behaviour from the repository name.

Inspect only the assigned material. After a bounded inspection, report findings and the proposed next action for review before expanding source access or changing authoritative meaning. Persist decisions, evidence, unresolved questions, and the next entry point. Any source read must appear by exact path in the active assignment. Apply the repository-wide entrypoint and RULE-PRJ-001 for mutation and commit gates.
